## 本次更新

修掉「新建食谱」粘贴菜谱时两个影响输入的毛病。都不丢数据，纯粹是键盘弹起后的排版问题，但每次写菜谱都会碰到。

### 修复

- **最后一段文字被键盘挡住**：App 用了 `enableEdgeToEdge()` 之后窗口不再随键盘缩放，而界面没有任何一处处理输入法占位，键盘一弹起内容原地不动，排在下面的文字就看不见了。现在编辑页正确让出键盘高度
- **光标手柄浮在键盘上面**：同一原因。选区手柄按光标位置绘制，而光标那行正被键盘盖住，手柄就画到了键盘上方。修好后手柄跟着文字一起上移，不会再越界
- **输入框被键盘遮住**：滚动列表不会因为输入框获得焦点就自动滚过去。现在菜名、整体备注、步骤标题、分钟四个输入框获得焦点时都会自动滚进可视区
- **粘贴区改为独立弹层**：原来粘贴框嵌在列表中间，天然受滚动容器限制。现在改为从底部升起的独立面板，输入框独占一屏，识别结果单独滚动，写长菜谱时不再需要一边打字一边找位置

## What's new

Fixes two input problems on the "New recipe" screen when pasting recipe text. Nothing is lost — it is purely a layout problem once the keyboard appears, but it hit every time you write up a recipe.

### Fixes

- **The last lines were hidden behind the keyboard**: after `enableEdgeToEdge()` the window no longer resizes with the keyboard, and nothing in the UI consumed the IME inset, so content stayed put when the keyboard rose. The editor screen now properly reserves the keyboard height
- **The selection handle floated on top of the keyboard**: same cause. The handle is drawn at the cursor position, and that line was underneath the keyboard, so the handle appeared above it. It now moves up together with the text and stays in bounds
- **Text fields were covered by the keyboard**: a scrolling list does not scroll to a text field just because it gained focus. The dish name, overall notes, step title and minutes fields now bring themselves into view when focused
- **Paste area is now its own sheet**: the paste box used to be embedded mid-list and was bounded by the scrolling container. It is now a modal sheet that rises from the bottom, with the input occupying its own space and the parsed result scrolling separately — no more hunting for the caret while writing a long recipe
