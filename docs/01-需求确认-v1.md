## 三、数据模型草案（先定模型，避免后期重构）

```
Recipe(流程模板)        1 ── n  Step(节点：顺序、标题、时长秒、默认备注)
Recipe                   1 ── n  Cook(session 实例：名称、开火时间、状态)
Cook                     1 ── n  CookStep(实例节点：状态 pending/running/done、
                                        startedAt、expectedEndAt、实际完成时间、实例备注)
```

关键点：
- **模板与实例分离**：同一食谱开 3 份互不影响；改模板不追溯改历史实例。
- **备注两层**：模板默认备注 + 实例覆盖备注，实例改动不回写模板。
- **时间基准**：墙钟（`currentTimeMillis`）算到期时间，`elapsedRealtime` 校正息屏误差；单一调度器每秒 tick，不每个计时器各开协程。
- **导出格式**：`{schemaVersion, exportedAt, recipes[], cooks[], settings}`，Gson 序列化，导入按 schemaVersion 分支迁移。

## 四、技术选型

- Kotlin + Jetpack Compose（Material3）+ Room 2.6.1 + KSP；单模块、MVVM、手动 DI（不引 Hilt，减少依赖面和构建时间）
- minSdk 24 / targetSdk 34（与既有项目一致，覆盖绝大多数在用手机）
- 语言：SharedPreferences 存 `lang`，比系统 Locale 优先（沿用 `inventory-android` 已验证的 I18n 做法）
- 状态：StateFlow + ViewModel；倒计时用前台 Service 承载，UI 只做展示

## 五、应用内更新与安装

1. 启动或手动点"检查更新" → 调 GitHub Releases API 取最新 tag
2. 比对 versionCode → 有新版则展示双语更新说明
3. 下载 APK 到**应用私有目录**（`getExternalFilesDir`，Android 上属于手机存储，不涉及 C 盘）
4. 校验 SHA256 + 签名一致性 → 弹窗二次确认 → `REQUEST_INSTALL_PACKAGES` + FileProvider 调起系统安装器
5. 下载失败/校验不符 → 删除残包并提示，不静默安装

**"不落 C 盘"的落地口径**（需你确认）：这台开发机上——Gradle 缓存、构建产物、APK 下载、快照归档全部指向 `F:/android-dev` 与 `D:`；App 运行时的下载落手机应用私有目录。

- 建仓 → 推 main → 打 tag → Release 附 APK + SHA256 + 双语 Release Notes → Pages 部署 `docs/`（`index.html` 中文 + `en/` 英文）

- keystore 与 `keystore.properties` 已在 `.gitignore`，不进仓库

## 七、备份与回滚

- 每次高危改动前：`git commit` + 打 tag + 整目录 zip 快照到 `F:\deepseek-harness\_archive\<日期>-cooktimer\`
- 回滚 = 恢复快照目录 + 重新 checkout tag；脚本 `scripts/snapshot.ps1` 固化流程
- App 内数据：导入前自动备份当前库到 `backups/`，导入失败自动还原
